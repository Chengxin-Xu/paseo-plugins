# 服务器浏览器 Server Browser 0.12

0.10.1：修复 Android App 的 Hermes 默认求值器无法加载最近画面缓存：改用闭包，保留逐主机隔离、访问顺序淘汰、字节预算、过期和卸载清理。


Paseo 插件：在 daemon 所在的 Linux 主机上运行 Chromium，手机和电脑在 Paseo 面板里看同一幅实时画面，可以点击、输入和导航；
浏览器 Agent 通过专用 MCP 操作同一个会话，你随时可以接管。无需另外暴露远程桌面或浏览器端口。

- 要求 Paseo 0.11.1 及以上，daemon 主机为 Linux。
- 内置英文和简体中文，默认跟随系统语言，也可以添加自己的语言。插件市场用的英文介绍见 [OVERVIEW.md](OVERVIEW.md)。
- 插件只使用 Paseo 宿主提供的库，没有运行时 npm 依赖，安装时不执行任何构建命令；浏览器运行时需要在主机上单独准备一次，见下文。

## Languages / 语言

在 **Paseo 设置 → 插件 → 服务器浏览器 → 语言** 中选择 **跟随系统**（默认）、**English** 或 **简体中文**。更改后，已打开的插件界面会更新，不必刷新页面；设置保存在当前 daemon，重新连接后仍然生效。跟随系统时使用设备语言，没有对应翻译时显示英文。网页内容和已经保存的 Agent 回复保留原来的语言。

自定义语言放在 daemon 主机的 `~/.paseo/plugin-data/server-browser/locales/`；设置了 `PASEO_HOME` 时，则为 `$PASEO_HOME/plugin-data/server-browser/locales/`。语言设置里显示实际目录、翻译覆盖率和文件问题。

1. 复制目录里的 `templates/en.json`（或 `templates/zh-CN.json`），放到 `locales/`，以语言代码命名，例如 `ko.json` 或 `pt-BR.json`。
2. 把 `$meta.name` 改成语言自己的名称，例如 `"$meta": { "name": "한국어" }`。保留分组名和消息键，只翻译值。
3. 原样保留每个 `{placeholder}`。复数形式使用 CLDR 分类（如 `one`、`other`），必须保留 `other`；各形式使用同样的占位符。
4. 在语言设置里点击 **重新读取**，再选择自己的语言。缺少或无效的条目回退到英文；占位符错误等问题会在设置里列出，不必一次翻译完。

同名的 `en.json` 或 `zh-CN.json` 可以只覆盖部分内置条目。插件更新会重写 `templates/`，不会改写自己的语言文件；可对照新模板补充新增条目。

要贡献内置语言，请提交 PR：新增 `shared/locales/<code>.json`，保留现有消息键与占位符，并在 `server/locales.ts` 的 `BUILTIN_CATALOGS` 中加一行注册对应目录（需要的导入一并补充）。

## 界面

侧栏打开 **服务器浏览器**。网页占据几乎整个面板，四周只有很薄的一圈工具：

- **电脑（两行）**：第一行是浏览器标签，每个工作区的浏览器一个；圆点颜色代表项目，多个项目时标签前显示项目标记和项目名。
  标签只切换你在看哪个浏览器，不改动网页。左侧 **所有浏览器** 打开总览，**+** 打开任意工作区（包括还没启动浏览器的），
  右侧 **打开 Agent** 跳到关联 Agent。第二行是后退 / 前进 / 刷新、地址栏、网页标签数、网页键盘、**Agent / 手动** 切换和 **⋯**。
- **手机（一行）**：顶部是当前浏览器（点它回到总览列表）、**Agent / 手动** 切换和 **⋯**。
  切到手动后，底部出现后退、刷新、地址栏、网页标签和键盘，方便单手操作；交还 Agent 后收起。
  Agent 模式下 **⋯** 里有“切到手动并后退”“切到手动并刷新”“切到手动并打开网址”。

**谁在控制一目了然。** 选中 **Agent**（紫色）时网页只读，Agent 可以操作；选中 **手动**（琥珀色）时 Agent 的写操作会被拒绝，它也读不到页面结构、网络请求和控制台记录，只能用截图看页面，
所以你这时输入的密码不会进入它的模型会话；你可以点击、滚动、输入和导航。网页四周的细边框和操作记录里的来源用同样的两种颜色。Agent 正在执行某一步时切到手动，
会显示“等待 Agent 结束当前操作…”。Agent 模式下点后退、前进、刷新或在地址栏回车，会先询问“切到手动并后退？”等，
确认后切到手动，等 Agent 做完当前这一步（最多 10 秒），页面没有变化才执行；Agent 期间换了页面时不执行，提示你看清后再操作。
确认只对打开确认时看到的页面有效：之后网页换了文档、切了标签页或改了画面尺寸，确认框变红、确认按钮停用，服务器也会拒绝，
既不切到手动也不执行；Agent 在同一页面上执行的步骤不会让确认失效。
标签上的小标记表示 Agent 正在操作浏览器（蓝色旋转）、等待审批（琥珀色闪动）、
需要登录（橙色）、出错（红色）或已手动接管（琥珀色指针）；等待审批和疑似需要登录时，画面上方会出现可关闭的提示，
直接 **打开 Agent** 或 **手动接管**。

项目颜色由项目名决定；蓝色表示进行中，琥珀色表示等你处理，红色表示出错，灰色表示未启动。旋转和闪动在后台暂停，
系统开启“减少动态效果”时不播放。

**所有浏览器** 在电脑上是缩略图网格，在手机上是按项目分组的列表：显示项目标记、Agent、项目与工作区、当前网页、
谁在控制，以及“Agent 操作中”“待审批”“需登录”等彩色状态，可搜索并筛选“Agent 进行中”“待接管”（带数量）。缩略图每个网页只取一次，
不会持续轮询；点击只切换查看对象，不导航网页，也不接管另一个任务。

**Agent 运行中不等于正在操作浏览器。** 总览只列出已经创建的服务器浏览器会话；没有接入本插件的普通 Agent、
Paseo 自带的浏览器工具不会被当成操作者。每个工作区有独立的浏览器和登录目录，每个工作区的浏览器关联一个专用浏览器 Agent。

## 使用

- **入口**：侧栏、工作区面板、Command Center（“打开服务器浏览器”“打开当前工作区的服务器浏览器”）和 `/server-browser`。
- **网页标签**：点地址栏旁的数字（手机在 Agent 模式下为 **⋯ → 标签页**）查看全部标签；手动时可切换、固定、关闭或新建。
  默认最多 20 个标签，达到上限时拒绝新建；固定的标签要先取消固定才能关闭。
- **操作**：手动模式下点击网页。电脑上点一下画面后可以直接打字，连续输入和回车按顺序送达，画面刷新不会打断；
  中文等输入法直接在画面上组合，组合期间画面右上角显示“输入法组合中”和正在组合的拼音，选好的词一次送出。
  组合只对开始时的标签页和文档有效：组合期间页面或控制方变了，没确认的文字会丢弃并提示，同时释放键盘，点一下画面或按 Tab 再继续输入。
  ⌘/Ctrl+V 按纯文本粘贴，长文本按整个字符分段发送，表情不会被切开；⌘/Ctrl+A 全选，
  其他快捷键留给 Paseo 和你的浏览器。点 **键盘** 打开输入栏，可输入较长的文字，并发送 Enter、Tab、退格、全选、Esc 和上下滚动；
  手机点画面不会弹出系统键盘，请用输入栏。鼠标滚轮或手机在画面上滑动可以滚动网页。
- **多端协作**：点击绑定当时显示的那一帧画面；另一台设备或 Agent 已经改变画面时，点击会被拒绝，请在新画面上再点。
  打字、按键和滚动绑定页面本身：同一个标签页、同一份文档、同样的画面尺寸和控制方，不必等新画面；网页或其中的 iframe 用 History API 改地址不算换页面。
  另一台设备开始输入、Agent 执行一步、网页弹出对话框、切换标签页（切走再切回也算）、改画面尺寸或设备预设、
  跳到新文档（例如回车提交后打开的新页面）、原地改写文档（`document.open()` 或返回 HTML 的 `javascript:` 地址），
  或网页里的 iframe 换了文档时，旧页面上还没送出的输入会被丢弃并提示有几个字没发出，
  不会补发到新页面。网页已经弹出对话框时，没发出的文字不算送达：提示有几个字没发出，输入栏保留草稿，提示里可以直接 **查看对话框**。
  缓存画面和尚未加载完成的图片不可操作。显示同时观看的客户端数量，同一个人的多台设备分别计数，
  停止观看后最多约 15 秒从计数中移除。
- **网页对话框**：网页的提示、确认和文字输入对话框会显示在面板中，手动模式下可以确认、取消或填写文字；Agent 模式下可用
  `browser_handle_dialog` 应答。对话框绑定自身的标签页与标识，另一端处理后不能重复提交。
  对话框一直等待明确应答；关闭面板弹层不等于取消网页操作，可从提示或菜单重新打开。多标签的对话框按出现顺序处理。
- **画面尺寸**：**⋯ → 匹配窗口** 按可用区域设置网页尺寸；**完整宽度** 检查网页内部的横向溢出并单独展开
  被挤出的右侧内容。仅观看、切换设备不会改动共享浏览器尺寸。“匹配窗口”最大 2560×1600，只在手动模式下可用。
- **设备仿真**：在 **⋯ → 画面** 选择桌面、手机或平板预设，同时设置视口、DPR、触摸能力、移动模式和 User-Agent。
  所有预设仍使用 Chromium 引擎。Chrome 预设的 User-Agent 和 Client Hints（品牌、平台、是否移动设备）跟随实际的 Chromium 主版本，
  格式同 Chrome 的精简 UA；Safari 预设只改 User-Agent，不发送 Client Hints；改回自定义尺寸时恢复 Chromium 自己的 UA。
  仿真沿用当前浏览器与登录目录，不通过重建浏览器清空 Cookie；如站点按首次请求的 UA 返回不同页面，可主动刷新。
- **⋯ 菜单**：画面（画质、尺寸预设、暂停与刷新画面、传输数据）、本工作区服务、用本机浏览器打开、打开或连接浏览器 Agent、阅读页面、
  页面诊断、操作记录、资源与恢复、打开演示页、关闭当前标签页和关闭浏览器（需确认）。只能在手动模式使用的操作，
  在 Agent 模式下不出现在菜单里。
- **阅读页面**：用 Readability 提取正文并转成 Markdown，也可读取完整可见文字或按关键词查找；长内容会标明截断。
- **页面诊断**：只读检查 Chromium 与调试连接、Chromium 沙箱、Profile、字体与运行库、Agent 工具、代理设置，以及当前页面的登录提示、
  HTTP 401/403 和网络错误。页面可读取不等于已经登录。
- **本工作区服务**：**⋯ → 本工作区服务** 和标签页面板列出这个工作区的服务脚本（`paseo.json` 里类型为 service 的脚本）
  及其运行和健康状态。手动模式下点运行中的服务，会在新标签页打开 `http://127.0.0.1:<端口>/`，由服务器上的浏览器访问；
  未运行的服务在 Paseo 里启动后点 **刷新**。
- **孤儿浏览器**：从总览进入列表。“仍在运行”列出已不属于当前工作区、但 Chromium 还在运行的浏览器，可以停止；
  “留下的浏览器资料”列出已归档或已删除的工作区留下的数据目录，显示工作区名称、占用空间和最后使用时间。
  删除资料需要再确认一次，会清掉其中的登录状态、Cookie、历史、缓存和 Agent 截图，不能恢复；仍在运行的要先停止。
  工作区归档会自动停止 Chromium、取消自动恢复、释放会话资源，但保留资料；工作区恢复后，之后的工作区列表里再次出现它时，浏览器可以重新启动。
  在这里停止或删除的浏览器同样如此，包括插件启动前就已归档、没收到归档通知的工作区。
- **用本机浏览器打开**：用手机或电脑的默认浏览器打开当前网址（Paseo 桌面端另有“在 Paseo 本机浏览器打开”）；本机打开不共享
  服务器浏览器的登录状态，localhost 指向你自己的设备。

## 画面与流量

画面是服务器端截取的 JPEG，通过 Paseo 插件 RPC 传给客户端，不是视频流，不承诺固定帧率。

- 手机只传看得见的像素：画面按画面区大小（像素比最多按 2 计）在服务器端缩小后再传，点击坐标不变。
- 同时只有一个画面请求，间隔不短于往返时间的两倍；画面到达慢时临时降低画质，网络恢复后回到所选画质。
- 页面和会话没变化时，每次轮询只有几十字节；应用在后台或面板被切到隐藏标签时暂停轮询。
- 切换浏览器时先淡显上次看到的画面，拿到新画面后替换。
- 网页跳到新文档（例如回车提交表单）时，进行到一半的截图会立即重新截取，画面马上跟上，不会等到截图超时。
- 最近画面缓存最多保留 12 项、8 MiB（按字符串内存估算），5 分钟未访问过期；已停止、已从总览移除的会话以及宿主断开、插件卸载时会清理。
- 未启动或启动中的面板也会在前台检查状态，另一端启动成功后自动显示画面，不因观看设备不同而改写浏览器尺寸。

## 浏览器 Agent

**⋯ → 连接浏览器 Agent** 用你选择的 Agent Profile（默认列表里的第一个）在该工作区新建一个 Agent，并只给它一个名为
`server_browser` 的 MCP 服务器；随后发送一条简短的准备消息（会用掉一次模型回合），然后把控制权交给 Agent。
已有的其他 Agent 不会被修改，也不会全局抢占 Paseo 自带的浏览器工具。

关联的 Agent 已关闭（未载入）时仍然算作可用，打开时由 Paseo 自动载入，不会再建一个新的；重新连接时优先复用已保存的
那个 Agent。只有已归档或已不存在的 Agent 才会被替换。暂时无法查询 Agent 状态时会提示重试，不会把连接失败当作已归档并直接创建替代 Agent。

`server_browser` 是通过一个小 bridge 连接到这个浏览器的 Playwright MCP。bridge 由插件按自己的源码（`server/bridge-source.ts`）
写入数据目录，Agent 用 daemon 的 Node.js 运行它：

- 只提供一份固定清单里的 Playwright MCP 0.0.82 工具，清单外的工具（包括以后版本新增的）一律拒绝。
  只读：快照、查找、等待、截图、控制台、网络请求列表与响应；写操作：导航、后退、点击、输入、填写表单、按键、选择、悬停、拖动、
  拖放文件、上传文件、处理对话框、在网页内执行 JavaScript、调整尺寸、模拟媒体特性、标签页；另有插件自带的阅读页面和页面诊断；
- 手动模式下拒绝所有写操作，也拒绝读取页面结构（`browser_snapshot`、`browser_find`、`browser_wait_for`）、网络请求和控制台记录：
  页面结构里有表单框中已经填写的内容，密码框也是明文；网络和控制台记录里有你接管期间提交的表单和令牌。Agent 这时只能用截图看页面
  （密码框显示为圆点），另外仍可阅读页面正文（不含表单内容）和做页面诊断，所以你接管期间输入的密码不会进入它的模型会话。
  申请操作时和调用 Playwright MCP 前各检查一次；判断依据是工具名，插件更新前就已启动的 Agent 会话同样受限。不允许 Agent 关闭共享浏览器；不提供 `browser_run_code_unsafe`
  （会在 MCP 进程里执行任意 Node.js 代码）；
- 网络请求只提供列表和响应：`browser_network_request` 的 `part` 只能是 `response-headers` 或 `response-body`，请求头和请求正文一律拒绝，
  因为其中可能有提交的密码、登录令牌和 `Authorization` 头（不带 `part` 的完整详情也包含请求头）。Playwright MCP 会一直保留标签页的请求记录，
  直到 Agent 自己在这个标签页导航，所以你接管期间发出的请求在交还后仍在列表里，Agent 能看到它们的地址和响应；
  控制台记录也一样，保留到网页跳到新文档为止；
- 导航和面板地址栏走同一套规则：只允许 HTTP/HTTPS，拒绝地址里的账号密码以及链路本地和云服务器元数据地址，交给 MCP 的是规范化后的地址；
- 上传（`browser_file_upload`、`browser_drop`）的每个文件先解析真实路径，必须是该工作区目录里的普通文件，符号链接和目录外的文件一律拒绝；
- Playwright MCP 只从运行时目录的 `node_modules/@playwright/mcp/cli.js` 启动，工作目录是该工作区目录，
  截图、快照等按文件名保存时只能写进工作区目录或该浏览器的 `artifacts/`，而且只有 daemon 用户可读写（0600）；它只继承 PATH、HOME、语言、时区、临时目录和 XDG 目录等环境变量，
  不继承 Agent 环境里的密钥、`NODE_OPTIONS`、代理和 `PLAYWRIGHT_MCP_*` 设置；
- 每次调用仍按 Agent 自己的审批设置处理。网页不能通过 WebMCP 给 Agent 注册工具。

Agent 读到的内容都会进入它的模型会话，包括所有打开的标签页的完整地址（含查询参数和 `#` 片段，Playwright MCP 的回复里就列着；
插件自己的回复只去掉地址里的账号密码）。交还 Agent 之后，页面结构又能读到：表单框里还留着的内容（包括没提交的密码）会出现在
Agent 读取的快照里，它的点击、输入等操作也会把整页快照写进 `artifacts/page-*.yml` 并在回复里给出路径。请提交登录表单之后再交还。

插件重载或 daemon 重启后，浏览器在后台恢复；浏览器 Agent 的 MCP 启动时若浏览器正在恢复，会最多等待 20 秒。

## 运行时准备

插件本身不下载、不安装任何软件。首次使用前，在 daemon 主机上准备一次运行时：

```sh
node scripts/setup-runtime.mjs          # 安装固定版本的运行时依赖，然后检查
node scripts/setup-runtime.mjs --check  # 只检查，不安装
```

- 在插件目录里运行。目录安装就是你的源码目录；从 Git 或插件市场安装时，路径见 `paseo plugin ls --json` 输出的 `path`。
- 脚本把插件附带的 `runtime-deps/package.json` 和锁文件 `runtime-deps/package-lock.json` 复制到运行时目录，再用
  `npm ci --ignore-scripts` 按锁文件安装 `@playwright/mcp@0.0.82`、`@mozilla/readability@0.6.0`、`jsdom@26.1.0`、`turndown@7.2.4`
  及其全部下层依赖，每台主机装出同一棵依赖树。来源是主机 npm 配置的 registry，禁用安装脚本；运行时目录原有的 `package.json` 会被替换。
  它不下载 Chromium，也不修改 Agent 配置或创建浏览器 Profile。
- 插件会从运行时目录加载代码，所以它必须是当前用户自己的真实目录（不能是符号链接）；脚本和插件都会把它设为 0700，
  不符合时拒绝使用并说明原因。
- **Chromium**：插件依次使用 `PASEO_SERVER_BROWSER_EXECUTABLE`、Playwright 缓存（`~/.cache/ms-playwright` 或 `PLAYWRIGHT_BROWSERS_PATH`）
  中最新的 `chromium-headless-shell`、运行时 Playwright 自带版本。没有时可以用运行时里的 Playwright 安装 headless shell
  （从 Playwright 的下载源获取）：`node <运行时目录>/node_modules/playwright/cli.js install chromium-headless-shell`。
- **系统库与字体**：Chromium 使用主机的系统库和字体。缺少的动态库（例如 `libgbm.so.1`）可以放进运行时目录的 `lib/`，
  插件会把它加入 Chromium 的 `LD_LIBRARY_PATH`；运行时目录里有 `fonts.conf` 时作为 `FONTCONFIG_FILE`。中文网页需要中文字体。
- 准备完成后用 **⋯ → 页面诊断** 确认 Chromium、Agent 工具、字体和代理都已就绪。运行时缺失时，启动浏览器会直接提示缺什么。

| 环境变量（daemon 进程） | 用途 | 默认 |
| --- | --- | --- |
| `PASEO_SERVER_BROWSER_RUNTIME` | 运行时目录（Playwright、MCP、正文提取库，可选 `lib/`、`fonts.conf`） | `~/.local/share/paseo-server-browser` |
| `PASEO_SERVER_BROWSER_DATA` | 各工作区的浏览器数据目录 | `<运行时目录>/visual` |
| `PASEO_SERVER_BROWSER_EXECUTABLE` | 显式指定 Chromium / Chrome 可执行文件 | 自动查找 |
| `PASEO_SERVER_BROWSER_PROXY` | 只给共享浏览器设置代理（`host:port` 或 `scheme://host:port`；含账号密码时拒绝启动，因为它会出现在 Chromium 命令行里） | 不设置时沿用 daemon 的 `HTTP(S)_PROXY` / `ALL_PROXY` |
| `PASEO_SERVER_BROWSER_SANDBOX` | `1` 总是开启 Chromium 沙箱（主机不支持时启动失败）；`0` 总是关闭 | 不设置时自动：先开沙箱，主机不支持时改用 `--no-sandbox` 并在页面诊断里提示 |

## 数据与隐私

每个工作区的数据在 `<数据目录>/<工作区 ID>/`。数据目录、工作区目录、`profile/`、`artifacts/` 和运行时目录在使用前都会检查：
必须是 daemon 用户自己的真实目录（不能是符号链接），并设为 0700，否则拒绝启动并说明原因。插件写的 JSON 文件为 0600：

| 路径 | 内容 |
| --- | --- |
| `profile/` | Chromium Profile：Cookie、登录状态、历史和缓存。按私人浏览器数据保管。 |
| `state.json` | 控制模式、网页尺寸、设置、恢复计数和已打开标签的地址，用于恢复浏览器。地址只保存 HTTP/HTTPS，去掉账号密码、`#` 后的片段，以及名字像一次性凭据的查询参数和路径参数：`code`、`state`、`token`、`session`、`sig`、`ticket`、`otp`、`totp`、`pin`、`pass`、`hash`、`hmac`、`assertion`，`verification_code`、`sms_code`、`invite_code` 这类 `*_code`（`country_code`、`zip_code` 等表示地区、语言、币种的除外），`;jsessionid=` 等。这是按参数名判断的启发式规则，不保证认全；其他参数保留。 |
| `session.json` | 本机连接信息、工作区目录（用于限制上传）和随机令牌。令牌只对这个工作区的浏览器有效，每次启动更换；文件只给本机 MCP bridge 使用，浏览器停止时删除。崩溃、强制结束或重启后留下的旧文件不再可信：bridge 只在其中记录的 Chromium 仍以这个工作区的 Profile 运行时才使用它，插件启动恢复时删除浏览器已不在运行的旧文件。 |
| `agent.json` | 关联的浏览器 Agent ID（只读取 4 KB 以内的普通文件）。 |
| `artifacts/` | Playwright MCP 写入的文件：Agent 工具自动命名保存的截图、快照、网络请求和响应内容；浏览器 Agent 会话连接期间每个标签页的控制台输出（`console-*.log`，持续追加，也包括你手动接管期间的输出）；这期间网页下载的文件也可能存到这里（用网站给的文件名，见下）。这里的每个普通文件按同一规则清理：超过 48 小时或总量超过 256 MB 时自动删除较旧的文件（保留最新的一份和 5 分钟内的文件），也可在 **资源与恢复** 里立即按同样规则清理；子目录和符号链接不处理。 |

- 数据目录根部还有插件写入的 `mcp-bridge.mjs`。
- 网页下载的文件由 Playwright 为插件的浏览器连接建立的临时目录接收（系统临时目录下的 `playwright-artifacts-*`，只有 daemon 用户可读写），
  浏览器停止、重启或插件卸载时删除；daemon 被强制结束时可能留下，需要时手动清理。本版没有下载管理。
  浏览器 Agent 会话连接期间，Playwright MCP 可能用网站给的文件名把网页下载（包括你手动接管期间的下载）另存到 `artifacts/`，按上表规则清理；
  Agent 会在回复里看到文件名和路径。
- **操作记录** 只在内存里保留本次插件运行中最后 12 次操作的来源、类型、状态和目标页面，不记录输入内容、Cookie 或网址查询参数；
  10 秒内同一标签页上连续的同类输入合并成一条。
- 画面、网页标题和地址只通过 Paseo 的连接发给你的客户端；插件不向其他服务发送数据。Agent 读取的网页文字、快照、截图、地址、控制台和网络响应会进入它的模型会话（见上文「浏览器 Agent」）。
- 插件 RPC 的错误信息会显示在客户端，也会写进 daemon 日志；其中的网页地址一律换成「[网页地址]」，保存的最近一次失败原因也一样。
- 插件读取 daemon 的工作区列表和 Agent Profile（名称、provider、模型），只用于界面里的选择。
- **清理**：关闭浏览器或归档工作区都会保留 Profile。已归档或已删除工作区的资料可以在 **孤儿浏览器** 里删除；
  仍可用的工作区要删除登录状态和历史，先在面板 **关闭浏览器**，再删除对应的 `<数据目录>/<工作区 ID>/`。
  删除整个数据目录会清掉所有工作区的浏览器数据。

## 网络与进程

- Chromium 以 daemon 用户身份无头运行，使用该用户的网络，可以打开主机能访问的任何 HTTP/HTTPS 地址，包括 `localhost`、局域网和其他私有网络地址；
  能使用这个 daemon 的人都可以通过它浏览。
- 其他协议、在地址里写账号密码的请求，以及链路本地和云服务器元数据地址（`169.254.0.0/16`、`fe80::/10`、`fd00:ec2::254`、`100.100.100.200`、
  `metadata.google.internal`）会被拒绝。这些地址在 Chromium 内部也无法解析，网页脚本、跳转、iframe 和表单同样访问不到；
  但通过 DNS 解析到这些地址的其他域名拦不住。
- Chromium 关闭了后台联网和组件更新。代理见上表。Chromium 只继承 PATH、HOME、语言、时区、临时目录、XDG 目录、代理和字体等必要的环境变量；
  运行时目录有 `lib/` 时才把它加入 `LD_LIBRARY_PATH`。
- 进程：每个运行中的工作区浏览器一个 Chromium；每个浏览器 Agent 会话一个 Node.js bridge 和一个 Playwright MCP 进程。
- Chromium 调试端口和插件控制接口只监听 `127.0.0.1`。控制接口需要 `session.json` 里该工作区的令牌；**调试端口没有认证**：
  本机任何账号或进程连上它，就能拿到这个工作区 Profile 的全部 Cookie（包括 HttpOnly）和登录状态，读取页面内容，在已登录的网站里执行脚本，
  并绕过手动接管。调试地址已不出现在任何命令行里（Playwright MCP 从环境变量读取），但端口藏不住：其他账号读 `/proc/net/tcp` 就能找到
  监听 127.0.0.1 的端口，`hidepid` 只隐藏进程，不隐藏套接字。根本的修法是 Chromium 改用 `--remote-debugging-pipe`，再由插件提供一个
  需要令牌的本机代理给 Playwright MCP 连接；这要改写浏览器的启动方式和所有连接它的路径，本版没有做。**请只在不与他人共用的主机上使用。**
- 默认开启 Chromium 沙箱：网页进程在独立的用户命名空间和系统调用过滤中运行。主机不支持时自动改用 `--no-sandbox`，
  并在页面诊断里提示；`PASEO_SERVER_BROWSER_SANDBOX` 可以强制开或关。
- Agent 的每次操作都持有一个租约：浏览器 Agent 放弃等待的申请不会留下租约，2 分钟没有续期的租约自动失效，
  Agent 新开标签页时租约保留到页面加载完成或超时。读取标题、测量宽度和读取正文都有各自的时限，关闭浏览器不会排在卡住的操作后面。
- 这不是对本机全权限 Agent 的安全沙箱：授权的本地进程仍有自己的系统权限。

## 恢复与限制

- 浏览器意外退出后按 1、3、8 秒退避，5 分钟内最多恢复 3 次；恢复已保存的 HTTP(S) 页面、窗口尺寸、固定状态和 Profile，
  不重放输入、点击或表单提交。用户主动“关闭浏览器”后不自动恢复。客户端断开不会停止浏览器。
- 尚未写盘的新 Cookie、未提交的表单和网页内存状态不能保证在崩溃后恢复。
- 只支持 Linux daemon 主机，已在 x86-64 + Chromium headless shell 上验证；自动查找只认 x86-64（`linux64`）的 headless shell，
  其他架构请用 `PASEO_SERVER_BROWSER_EXECUTABLE` 指定。
- 没有下载管理、音视频和完整的键盘快捷键映射。剪贴板只能单向粘贴纯文本到网页，不能把网页里复制的内容带回本机。
- 输入法在电脑网页端验证（用调试协议模拟 Chromium 的组合事件，没有逐一验证各系统的真实输入法）；手机打字使用输入栏，不在画面上弹出系统键盘。
- 网页里的 iframe 每跳到一份新文档都会结束当前输入并提示，iframe 不停自动刷新的网页上打字会被打断。
- 用 `PASEO_SERVER_BROWSER_EXECUTABLE` 换成完整的 Chrome 或 Chromium 时，Chromium 默认做站点隔离，跨站 iframe 跑在独立进程里。
  插件会为每个这样的 iframe 单独接一个调试会话，用来发现它换了文档；默认的 headless shell 不需要这样做。
- 每个浏览器最多记住最近 64 台打过字的设备的输入序号，更早的设备被挤出后，服务器只记一个下限，新界面会自动从下限之上编号。
  插件更新后仍开着旧版界面的设备不知道这个下限：如果服务器已经不记得它，它打的字会被拒绝并提示，刷新页面换成新界面即可。
- 企业 SSO、验证码以及站点是否允许服务器访问，需要按站点验证；诊断只检查当前页面，不访问其他站点。
- 原生 iOS/Android 的代码使用 React Native 组件，但测试在手机尺寸的网页里完成。

## 开发与验收

```sh
npm ci --ignore-scripts
npm run typecheck
npm test          # 单元测试与真实 Chromium + MCP 集成测试，需要上面的运行时；使用临时 Profile，结束后清理
npm run test:ui   # Playwright 在桌面 1120×760 和手机 390×844 下检查界面，数据来自模拟预览
```

已有运行时的验收环境不需要重装依赖。用一个真实临时目录作为运行时根目录，将已安装的 `node_modules` 复制或写时复制到其中，
只读复用 Chromium、可选 `lib/` 和字体配置，再通过 `PASEO_SERVER_BROWSER_RUNTIME` 指到它。
运行时根目录不能是符号链接，`node_modules` 也不能链接到目录外，否则 MCP 可执行文件的真实路径校验会拒绝启动。
`PASEO_SERVER_BROWSER_DATA` 可进一步把测试数据放到另一个临时目录。若测试 daemon 需要浏览器，启动 daemon 前也要设置这些变量。
测试前清除 `PASEO_AGENT_ID`、`PASEO_AGENT_CWD`，并把 `PASEO_HOME` 指到临时目录，避免调用当前会话或默认 daemon。

- `npm run preview:build` 生成 `preview/dist/`（`node scripts/preview.mjs --serve` 在 `127.0.0.1:4196` 提供，可用
  `SERVER_BROWSER_PREVIEW_PORT` 改端口），不需要 daemon；数据与画面来自 `preview/fixtures.js` 和 `preview/fixtures/*.jpg`
  （由 `preview/make-frames.mjs` 渲染的虚构网页）。
- 缺少系统 Chromium 库的主机照常用 `LD_LIBRARY_PATH` 指向运行库；`BROWSER_TEST_EXECUTABLE` 可以指定测试用的 Chromium。
- `tests/live-*.mjs` 是连接真实 daemon 的验收脚本，不属于 `npm test`，必须显式指定工作区和 Profile，缺少配置时在连接前停止：

| 脚本 | 必填环境变量 | 操作范围 |
| --- | --- | --- |
| `live-agent-tabs-check.mjs`（`npm run test:agent-tabs`） | `BROWSER_TEST_WORKSPACE`、`BROWSER_TEST_LINKED_WORKSPACE`、`BROWSER_TEST_LINKED_PAGE_TITLE` | 只读核对两个已有会话及布局 |
| `live-ux-check.mjs`（`npm run test:ux`） | 同上 | 操作第一个工作区的演示页面，核对第二个会话保持 |
| `live-agent-check.mjs`（`npm run test:agent`） | `BROWSER_TEST_WORKSPACE`、`BROWSER_AGENT_PROFILE` | 创建或复用专用浏览器 Agent，执行演示交互和手动接管检查 |
| `live-typing-check.mjs`（`npm run test:typing`） | `BROWSER_TEST_WORKSPACE` | 启动该工作区浏览器并切到手动，打开本机临时表单页（另开一个标签页），在真实网页端的画面上按三种速度打字加回车、用输入法输入，并检查组合中途换文档或换标签页时文字不会送到任何页面，经调试端口核对网页收到的内容 |

需要两个工作区的脚本里，两个工作区必须不同，ID 从目标 daemon 中选择。界面入口默认 `http://127.0.0.1:6767`，可用 `BROWSER_TEST_BASE_URL` 覆盖，
WebSocket 地址可用 `BROWSER_TEST_DAEMON_URL` 覆盖；数据目录按 `PASEO_SERVER_BROWSER_DATA` / `PASEO_SERVER_BROWSER_RUNTIME` 解析。
测试报告和截图写到 `artifacts/`，已被 `.gitignore` 排除。
