# 拾页 · 项目手记（Project Notes）

Paseo 项目看板，版本 **0.12.0**，插件 ID `project-notes`。按项目记录任务、提示词和想法，并能从一条手记直接开工：新建工作区和 Agent，把手记作为第一条消息发出去；常用提示词可设为一键发送，任务卡上能看到它启动的 Agent 现在怎样。需要 Paseo 0.11.1 或更新版本（daemon 与 App 都要满足，旧版本会拒绝加载）。内置英文和简体中文，默认跟随系统，也支持用户自定义语言。

插件市场的说明页见 [OVERVIEW.md](OVERVIEW.md)，版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## Languages / 语言

在 Paseo 的 **Settings → Plugins → Project Notes → Language**（中文界面为「语言」）选择语言。默认「跟随系统」按设备语言选择，没有对应翻译时显示英文。切换后已打开的界面立即更新。CLI 从 `$PASEO_HOME/plugin-data/project-notes/i18n-state.json` 读取同一设置，没有固定语言时使用最近一次设备语言；没有状态时使用英文。已保存的手记和历史正文保持原文。

自定义翻译放在 `~/.paseo/plugin-data/project-notes/locales/`（设置了 `PASEO_HOME` 时位于其下的对应目录）。复制该目录内的 `templates/en.json` 或 `templates/zh-CN.json`，改名为语言代码，例如 `ko.json`；把 `$meta.name` 改成语言自己的名字。翻译各条值并保留 `{placeholder}`。复数使用 CLDR 的 `one`、`other` 等形式，必须提供 `other`。省略或无效条目回退英文；「语言」设置显示覆盖率和具体问题。保存后点「重新读取」再选择该语言。同名 `en.json` 或 `zh-CN.json` 可以覆盖部分内置文字；不要修改会在升级时重写的模板。

贡献内置语言时，提交 PR 添加 `shared/locales/<code>.json`，在 `server/locales.ts` 的 `BUILTIN_CATALOGS` 中增加一项并导入该文件。可以从现有目录复制，保持消息 ID、占位符和复数结构一致。

## 功能

- 按项目整理任务、提示词和想法，默认总览全部项目；不归入项目的记在「随手记」。
- 任务状态、编辑、重点、置顶、搜索、复制、回收站恢复，以及确认后的彻底删除和清空回收站。
- 项目与 worktree 共用项目归属，不同 daemon 独立存储。
- **开始处理**：用户选择项目、Local/worktree、provider、模型、推理档位或 profile 后，创建工作区和 Agent 并发送编辑后的初始任务。可选项全部来自 Paseo 当前报告的 provider、模型和 profile（含自定义 provider），插件不写死任何 provider；没有模型列表时使用宿主的 default 模型。工作区保留用户填写的标题，worktree 使用 `notes/<id>` 分支；创建时不请求宿主自动命名，不额外调用命名模型。独立启动记录和创建幂等键用于避免同一启动重复创建。被重载打断的启动按 Agent 标签、目标项目下的 worktree 标识找回已有资源，只查询、不补建；找到工作区后可打开核对，不能更换选项另建一次。
- 并发编辑使用 revision 校验；确认请求支持短期幂等重试。
- **省流量同步**：界面只在前台可见时轮询（切到后台、iOS inactive、隐藏的标签页都会暂停，回到前台立即检查一次）。每次请求带上次的内容版本号：没有变化只回约 60 字节；有变化回增量看板及已移除 ID，未知版本回完整快照。恢复低 revision 的磁盘备份也会同步；在途旧响应不能覆盖刚完成的本地写入。项目列表变了才带项目列表。约每 5 秒一次，一分钟无变化后放宽到每 15 秒；自己的修改立即显示，下一次仍携带原版本号，只刷新受影响的看板。
- **命令行 / Agent 记录**：`bin/notes.mjs` 直接读写手记，与插件共用数据文件，写入有跨进程锁。
- **一键发送**：常用提示词作为胶囊出现在每个 Agent 的输入框上方，点一下就发；会打断回合或取消审批时先问你，见下文「一键发送」。
- **任务卡状态**：从任务启动的 Agent 在卡片上显示运行中、等你处理、完成未读、出错等状态，点一下打开，见下文「任务卡状态」。

从侧栏「拾页 · 项目手记」、工作区面板、命令中心或 `/notes` 打开。`/notes` 不带文字时打开面板；`/notes <文字>` 保存一条「随手记 / 想法」。`/prompt [关键词]` 打开提示词库，不会自动发送。

## 提示词库与修改快照

- 当前会话输入框上方的「提示词」胶囊与 `/prompt [关键词]` 共用提示词库。先搜索、选择，再填入 `{{变量}}` 并预览；变量按字面值替换一次，不执行代码，也不改写命令、路径或反引号内容。
- 网页与 Mac 桌面胶囊在找到当前会话唯一输入框时提供「填入输入框」，已有草稿可选追加或替换，填入后可撤销；用户继续编辑后不会覆盖新内容。它依赖宿主的 `textarea[data-composer-input]` 约定，失效或原生 App 上继续使用「复制到剪贴板」。输入框附件菜单中的「项目手记」可以搜索全部项目及随手记，把任务、提示词或想法附加为草稿上下文。附件保留原文；含变量的提示词请先在胶囊填参并复制。
- 点选提示词只打开预览。「发送给当前 Agent」会重新检查会话状态：可插话时插话，空闲时发送；待审批或不支持插话的运行中会话要再次确认「中断并发送」（有审批时是「仍然发送」）。不会点一下条目就打断回合。确认时也可以选「等这一轮结束再发」（有审批时是「等审批处理完再发」）：提示词存进插件服务端的队列（`$PASEO_HOME/plugin-data/project-notes/deferred-send.json`），这一轮结束、没有待审批时用自己的消息 ID 自动发出，App 关着也照发。「发送给当前 Agent」也先把提示词全文写进这个账本再发出；发完只留前 160 字预览和结果，保存一周（界面上 30 分钟后就不再显示）；读不了的账本另存一份备查，最多 3 份、一周。选择器里列出这个 Agent 排队的提示词：「排队中」可取消；排队后会话里出现了别人的消息就停在「待确认」，可「仍然发送」或「取消」；送达等结果显示一阵后消失。只有还有提示词在等、App 在前台时每 5 秒刷新一次。「发送给当前 Agent」也由插件服务端发出：服务端拿到这个 Agent 的发送锁后按当时的状态再判断一次，要打断回合或取消审批而你同意的不是这些（比如确认之后又有了新审批，或者那一轮结束、又开始了新的一轮），就不发送，重新给出三个选择；同意后用同一个消息 ID 再发。Agent 没换轮次时只确认一次。发送或排队没收到回复时，再点一次按原来的消息 ID 重试，不会发两份。20 秒内没等到 Agent 开始这一轮，先显示「发送中」。同一条提示词（同一条手记、同样的参数）同一时间只有一条在路上（排队中、发送中、待确认），按服务端记录判断：选择器只显示「已排队」「发送中」或「待确认」，重新选择、重开选择器、换设备都一样；两台设备同时发送只发出一次。没收到发送结果时（插件重载、进程退出），这条停在「待确认」：服务端每分钟去会话记录里找一次，找到了就标「已送达（在会话记录里找到了这条消息）」；「仍然发送」也先查会话记录，没有、且上次发送已过两分钟才重发。未载入（closed）的会话也可发送，已归档会话不可用。斜杠提示词按 provider 的实际能力判断是否需要中断确认。一条提示词最后是「可能已送达」（比如取消了结果不明的那一条）时，选择器提示上次的发送结果不确定，请先核对会话再决定要不要重发。
- **斜杠命令前先移除输入框全部附件。** Paseo 0.11.1 在有附件时会跳过插件命令，把 `/notes` 或 `/prompt` 当成普通消息发送给 Agent；插件无法拦截宿主的这条路径。附件应通过宿主的正常消息流程发送。
- `/notes <文字>` 把文字存为「随手记」里的想法，不请求模型；`/notes` 打开项目面板。胶囊与附件源按需查询，搜索最多返回 40 条。
- 每条手记的标题、正文或类型改变时保存最近 10 次修改前快照；状态、重点、置顶和移入/移出回收站不占版本。历史保存在独立旁路文件，旧看板首次读取或写入时自动迁出全部历史，先保存历史再移除主文件副本。总览、增量和 CLI `--json` 默认不带历史；详情「修改快照」或 CLI `show --history` 按需读取。恢复快照生成新版本并保留恢复前内容。迁入的旧版本在旁路保留，新产生的历史按最近 10 版轮换。已提交版本键也保存在旁路中，主看板缺键时据此恢复，不把缺键当作淘汰历史的依据。
- 看板文档读取兼容版本 1、2，写入一律使用版本 2；迁移也会升级文档版本。**升级后不能直接回滚到 0.9.0**：旧版会拒绝读取版本 2，看板和命令行工具应同时升级。请备份并一起恢复主看板和 `boards/history/`。只恢复主文件导致快照缺失时，详情会说明缺失数量；可先找回备份，或点击「放弃缺失的快照并继续」，再点「确认放弃缺失快照」。确认只移除确实缺失的引用，保留当前正文和现存快照，之后可继续编辑；未确认时阻止正文覆盖。CLI 的 `show --history` 会提示缺失情况，JSON 包含 `historyMissing` 和 `historyMissingCount`；CLI 用户可从界面详情完成这次确认。
- 提示词编辑器可「生成四段模板」，保留已有草稿和段落，补齐目标、范围、约束、验收。仅只读探测所选项目根目录的固定配置文件，识别语言和测试入口，不执行测试、不读取源文件或凭据；未知项保留 `{{变量}}` 供填写。
- 「开始处理」以用户编辑后的「初始任务」为正文，来源放入标题为「手记 #短ID · 标题」的文本上下文附件（`contextKind: project-notes`）；附件只含项目、状态、重点、手记编号和标题，不携带原正文。Paseo 0.11.1 会剥除自定义 `contextKind`，但保留来源附件的标题和文本；需宿主支持后才能保留该标识。这里与用户在输入框附件菜单中主动附加手记全文的功能不同。
- 连接中断后，可用「重试这次请求」重放同一启动。找回过程覆盖准备中、创建工作区中及无资源标识的不确定状态，按目标项目分页列出工作区并核对 `worktreeSlug`；查到后补存工作区标识，隐藏「修改选项重试」。明确在创建前拒绝、确认尚未创建资源时才可更改选项另开一次。Local、缺少定位信息的旧启动记录或查询失败时保留「需要核对」，不允许换启动标识重建。另一台设备修改正文会提示「手记已更新」，仅在点击「载入最新手记」后替换草稿。
- 大看板使用虚拟列表，搜索等待 160 毫秒输入停顿，复用规范化正文索引，摘要最多处理 2000 字符、显示 240 字符；打开详情仍能读到全文。

## 一键发送

- **打开**：在提示词详情点「一键发送」（再点一次取消）。这条提示词就以胶囊出现在每个 Agent 的输入框上方，排在「提示词」胶囊之后；标签取手记标题，过长截短。最多 12 条；超过 3 条时合成一个「一键 N」菜单胶囊，菜单末尾是「管理一键发送…」。手机和 1024 px 以下的窗口里一律收进这个菜单胶囊（英文界面只显示数字），以免宿主那一行放不下、把各插件胶囊的标签挤成一个字；窗口变宽（旋转、调整大小）时就地展开。
- **为什么是开关而不是置顶**：置顶只决定看板里的排序，一键发送是一份跨项目、跨设备共用的有序列表，顺序由你单独排，一条提示词可以置顶却不放进输入框上方，反之亦然。
- **点按时**：Agent 空闲、未载入，或正在运行但能插话（按宿主报告的 provider 能力判断，自定义 provider 按它继承的内置类型）时直接发出；正在运行又不能插话时，胶囊是一个菜单：「等这一轮结束再发」或「中断并发送」；有待审批时是「等审批处理完再发」或「仍然发送」。不会点一下就打断回合或取消审批。
- **怎么发**：和「发送给当前 Agent」走同一个发送账本（`deferred-send.json`，规则见上一节）：插件服务端重新读这条手记，拿到这个 Agent 的发送锁后按当时的状态再判断一次。Agent 在你点下前刚变忙就不发，胶囊改成上面的菜单并提示再点一次；同一条提示词同一时间只有一份在路上，与「提示词」胶囊和其他设备共用记录；没收到回复时显示「没有确认发送结果」，请先在「提示词」胶囊的队列或会话里核对；同一次连接内再点一次沿用原来的消息编号，不会发两份（App 重新连接后不保证）。结果用提示条告知，「等这一轮结束再发」的进度在「提示词」胶囊的队列里。发送部分不常驻：第一次点按时下载一个约 13.5 KB 的小分片（`/notes <文字>` 第一次记录时也一样），同一次连接只下载一次；加载和发送期间胶囊转圈、不能再点。
- **含 `{{变量}}` 的提示词**不能一键发出：胶囊显示花括号图标，点按打开原有的填写表单，填好后照常预览、发送；在「一键 N」菜单里点它，会在提示词库页打开同一个表单。服务端发现提示词新加了变量时同样拒绝，胶囊随即改为填写。
- **管理**：「提示词」页顶部的一键发送条显示输入框上方的样子，「管理」里可上移、下移、移除；手记已删除、在回收站或不再是提示词、含变量的条目会标出来。手记改了标题、加了变量或移进回收站，打开看板时同步到列表；回收站里的不显示胶囊，恢复后回来；彻底删除和清空回收站时一并移除。别处彻底删除的手记在列表里标「已删除」，点胶囊只会提示不能发送，可在管理里移除。
- **同步**：列表存为宿主设置（见「数据与隐私」），任何设备改了，宿主推送设置变更事件，各设备的胶囊随即更新，不轮询。胶囊逐位更新：位置和编号没变的原地更新，只从第一处变化起重新注册，切换列表时不闪烁。

## 任务卡状态

- 用「开始处理」从任务启动的 Agent，状态显示在任务卡上：运行中（蓝，跳动）、等你处理（琥珀，等审批或回答问题时呼吸）、完成未读（绿）、出错（红）、空闲（灰）；有子 Agent 时显示个数（带 `paseo.parent-agent-id` 标签的 Agent），再加最近活动时间。一条任务启动过几次时，卡片显示最需要处理的那个，再标「另 N 个」。点状态打开该 Agent。
- 任务详情的「启动记录」列出这条任务的全部启动：每个 Agent 的状态、provider、子 Agent 和时间，还在创建的、需要核对的、未启动的也在内；有 Agent 的行可「打开」。Agent 归档或删除后显示「已结束」，不报错，也不再可打开。
- 状态只来自 Paseo 的 Agent 目录订阅（本来就为输入框胶囊开着，胶囊与看板共用一份）和插件自己的启动记录（`launches/`），从不读会话记录，不会唤醒未载入的 Agent。看板只在前台可见时跟随目录变化；启动记录按 revision 查询，没变化只回 `unchanged`，有启动还没完成时每 4 秒查一次。动画只在前台播放，系统开启「减少动态效果」时不播放。
- 0.12.0 起启动记录带上手记编号。之前启动的 Agent 按已有的手记标签照常显示；已归档的旧 Agent 只在详情里列出，没建成 Agent 的旧启动不显示。

## 界面

- **一行工具栏**：项目范围（全部项目 / 随手记 / 各项目，带条数，可搜索）、任务 / 提示词 / 想法及条数、搜索、新建（手机上是「+」），其余放在「···」：回收站、按项目分组、刷新（提示保存在哪台主机、上次同步时间）。
- **任务**：宽屏是 待办 / 进行中 / 已完成 三列，各列独立滚动，列头「+」直接新建到该状态；手机上是可折叠分组（进行中在前，已完成默认收起）。卡片左侧的状态圈是唯一的快捷操作：点一下前进一步（待办 → 进行中 → 已完成 → 待办）。
- **提示词 / 想法**：列表每行都有「复制」；宽屏右侧直接显示全文与全部操作。
- **详情**：点卡片打开，含全文和全部操作——开始处理、编辑、复制、状态、置顶、重点、删除。删除直接移到回收站（无确认框，随时可恢复）。
- **编辑**：类型、保存到（新建时选择，之后固定）、标题、正文、状态、重点、置顶；「保存」在手机上固定在顶部、桌面固定在底部；标题里按回车即保存；别处改过时停用保存，可「载入最新」。
- **开始处理**：只默认展开项目、标题、初始任务和工作区方式；Agent 设置折叠为一行摘要，需要处理时自动展开。确认后表单收起为摘要，显示启动进度，完成后打开新会话。
- 同步状态平时不显示；手动刷新时显示「同步中」，同步失败时出现一行提示和「重试」。
- **颜色**：任务蓝、提示词紫、想法琥珀（类型切换、编辑器、行首图标、空状态一致）；待办灰色空心圈、进行中蓝色半圈、已完成绿色实心对勾（卡片、列头、分组标题、状态切换一致）；重点红旗、置顶琥珀图钉；项目用首字母色块，颜色按项目名计算，与其他插件里同一项目一致，随手记是青色收件箱。「开始处理」的进度区按阶段变色：进行中蓝、已开始绿、需要核对琥珀、被拒绝红。

## 安装

本目录是插件集合仓库里的一个插件。从 Git 安装时指定子目录 `project-notes`，把 `<owner>/<repo>` 换成发布这个集合的仓库：

```sh
paseo plugin add git:<owner>/<repo>:project-notes
paseo plugin ls project-notes
```

Git 安装会在插件目录执行 manifest 里的两步准备：`npm ci --omit=dev --ignore-scripts --no-audit --no-fund` 按锁文件只安装生产依赖 esbuild 和 zod（约 20 MB），`npm run build` 生成命令行工具 `bin/notes.mjs`。daemon 主机需要 npm，并能访问 npm 仓库。插件本身只用 Paseo 提供的库。

也可以从本机目录安装：`paseo plugin install /绝对路径/project-notes`。目录安装不会执行上述准备步骤；需要命令行工具时，先在插件目录运行 `npm ci --omit=dev --ignore-scripts` 和 `npm run build`（开发时用完整的 `npm ci` 即可）。

## 让 Agent 记录：命令行

在本插件目录内执行。`npm run build` 把 `server/cli.ts` 打包为 `bin/notes.mjs`，产物不进 Git。

```sh
node bin/notes.mjs --help
node bin/notes.mjs projects
node bin/notes.mjs list --project inbox --kind task
node bin/notes.mjs add --project inbox --title "待整理的任务" --high --body-file - <<'EOF'
多行任务说明…
EOF
node bin/notes.mjs update ITEM_ID --status doing
node bin/notes.mjs done ITEM_ID
```

将 `ITEM_ID` 换成已有条目的 ID。在其他目录调用时写插件目录的完整路径；通过 Git 安装时可用 `paseo plugin ls project-notes --json` 查看安装目录。

- `--project` 接受 `inbox`、项目 ID、绝对路径或项目名称；省略时先按 `$PASEO_HOME/projects/workspaces.json` 中已登记的 `cwd → projectId` 归属，再匹配项目目录。支持外置 worktree、子目录和符号链接，优先使用 `PASEO_AGENT_CWD`。
- `--kind task|prompt|idea`，`--status todo|doing|done`，`--high` 重点，`--pinned` 置顶，`--body-file -` 从 stdin 读正文。`--json` 输出机器可读结果。
- 命令行参数在运行期间对这台主机上的其他账号可见（`/proc/<pid>/cmdline`）：标题总在参数里，不要写机密；正文用 `--body-file -` 从 stdin 传，不要用 `--body`。
- `list` 默认排除已完成任务和回收站；`--all` 含已完成，`--trash` 只看回收站。
- `--request-id` 可选，最近 300 次确认请求内，同一 ID、同一修改内容的 create/update/done/delete/restore 会返回成功回执及当前看板，revision 改变不影响重试；同一 ID 换内容会被拒绝。旧版回执仅在原 revision 不变时兼容重放。接近存储上限时，删除或清空回收站会优先缩短旧回执窗口，以便清理空间。回执超出窗口后不再保证幂等，请换用新 ID 并先核对当前记录。参数错误退出码为 2。
- 项目列表来自 `paseo project ls --json`，不可用时回退读取 `$PASEO_HOME/projects/projects.json`（最多 8 MB，与前者的输出上限相同）。
- 界面在前台时约 5 秒（空闲后 15 秒）内看到 CLI 新记录：版本号由看板文件内容计算，其他进程写入同样生效。
- 读取有上限：正文最多 32000 字，在 UTF-8 下最多 96000 字节。`--body-file` 只读普通文件，先按大小拒绝超过 96000 字节的文件再读；目录、管道和 `/dev/zero` 这类设备不打开就拒绝。`-` 或 `/dev/stdin` 读 stdin，读到同样的上限即停。不限制路径：命令行在 Agent 自己的 shell 里运行，它本来就能读这些文件，路径白名单挡不住什么。
- 人读输出里，来自手记、项目名和路径的控制字符（ESC 序列、回车、退格、C1 控制字符）显示为 `\xNN`，换行和制表符保留；`--json` 输出不变。时间按 UTC 显示并标明 `UTC`。
- 不带 `--project` 的 `list` 与界面总览使用同一套体积上限：超限的看板不读取，在输出末尾列出（`--json` 里是 `unavailable`），其余项目照常列出。只因合计超限而略过的项目，仍可用 `--project` 单独查看。
- `list`、`show` 等读取命令也可能触发旧看板迁移，写入版本 2 主文件、历史旁路及锁文件；读取操作不能当作只读备份工具。升级后请重新构建 `bin/notes.mjs`，旧版工具会拒绝读取新格式。

CLI 和界面使用同一 `BoardStore`。`server/store.ts` 用 `<board>.json.lock` 排他锁串行化写入。锁文件记录持有者的 pid、随机令牌、主机名和 PID 命名空间，Linux 上另记进程启动时间：

- 等待者只在持有进程已经退出时接管，pid 被别的进程复用也算已退出；
- 无法核对的锁（内容读不出、来自别的主机或 PID 命名空间）超过 60 秒才清理；
- 几个写入者同时发现同一把残留锁时，经 `.reclaim` 守护文件逐个重新判断，只有一个接管；
- 持有者只删除自己的锁，提交前再确认锁仍是自己的，否则放弃这次写入并报错，不会覆盖别人的修改。

CLI 只依赖 zod 和本插件源码（`shared/schema.ts`、`server/store.ts`、`server/cli.ts`），所以只装生产依赖也能构建。

## 数据与隐私

```text
$PASEO_HOME/plugin-data/project-notes/boards/<项目ID的SHA256>.json
$PASEO_HOME/plugin-data/project-notes/boards/history/<看板SHA256>.<手记ID>.json
$PASEO_HOME/plugin-data/project-notes/launches/<launchId>.json
$PASEO_HOME/plugin-settings/project-notes/quick-prompts.json
```

未设置 `PASEO_HOME` 时默认 `~/.paseo`；源码目录不参与数据路径计算。移动、更新或卸载源码不等于迁移或删除笔记，请单独备份上述数据目录。

单个看板文件最多 32 MB。总览（界面和 CLI 的 `list`）一次最多带合计 32 MB 的看板，从小到大装入；单个超限或装不下的看板标为「暂时无法显示」，界面给出提示、项目列表标「不可用」，其余项目照常显示。合计上限取 32 MB，是因为总览回复是一个 WebSocket 帧：经 relay 时按 base64 密文传输，体积增大约三分之一，而宿主在客户端出站队列将超过 64 MB 时会断开连接。

笔记没有额外静态加密，不适合存密码或 API key。回收站不会自动清空；「彻底删除」和「清空回收站」需确认，删除后该条目及其旁路历史均不可恢复。「清空回收站」作用于当前项目范围内全部回收站条目，包含搜索未显示的条目，确认框会明确说明范围和数量。接近体积上限时仍允许清理；恢复和不增大数据的修改不会因预留空间被拒绝。

启动任务时，用户编辑并确认的初始任务及来源元数据会发送给所选 provider，附件不包含被用户从初始任务删去的原正文。启动记录保存阶段、创建的工作区和 Agent 标识、项目与隔离方式、启动参数（含初始任务）的 SHA-256 哈希（用来认出重复请求）、来源手记编号和项目、创建时间，以及 daemon 和 provider 报告的错误（截到 500 字），不保存提示词原文；启动记录不会自动清理。任务卡状态只读这些记录（普通文件，不跟随符号链接，单个最多 64 KB）和 Paseo 的 Agent 目录。一键发送列表 `quick-prompts.json`（0600，由宿主写入）存每条的手记编号、所属项目、标题副本、是否含变量、是否隐藏和手记版本，不存正文；一键发出的提示词和「发送给当前 Agent」一样先写进发送账本。其他手记的增删改只写插件自己的数据文件，插件不发网络请求、不启动子进程。拥有该 daemon 访问权的客户端都可以使用此插件。

## 开发

在插件目录运行：

```sh
npm ci --ignore-scripts
npm run build
npm run typecheck
npm test
npm run test:ui          # Playwright：桌面 1120×760 与手机 390×844 各跑一遍主要流程
npm run preview:build    # 模拟数据预览：preview/dist/index.html（加 --serve 在 127.0.0.1:4693 提供；PROJECT_NOTES_PREVIEW_PORT 可改端口，Playwright 读同一个值）
npm run preview:shots -- --out /tmp/notes-shots   # 各视图 × 桌面/手机 × 深色/浅色截图（--timezone 默认 UTC）
```

预览不连接任何 daemon：`preview/fixtures.js` 用内存里的虚构数据模拟全部 RPC（版本号、revision 校验、启动阶段），`preview/adapter.jsx` 按宿主方式提供图标（lucide）、弹窗（桌面 520 px 对话框、手机 65 % 底部弹层）、提示与剪贴板。`?theme=light`、`?scenario=empty|slow|error|stale|many|write-error|slow-write|copy-error|options-error|launch-hold|launch-reject` 切换状态，`?panel=1` 显示工作区面板，`?nav=0` 模拟不能跳转的客户端（启动完成后停在弹层里），`?view=quick` 打开一键发送管理，`?live=0` 去掉模拟的 Agent 目录和一键发送列表（任务卡不显示状态）。缺少系统 Chromium 依赖的主机需先设置 `LD_LIBRARY_PATH`。Playwright 与单元测试固定使用 UTC 时区。

测试使用系统临时目录（`tests/setup.ts` 把 `PASEO_HOME` 指向临时目录，绝不读写真实数据），覆盖：存储缓存与失效（含同大小原地修改）、损坏文件、体积上限与总览降级、跨进程锁（等待、超时、持有者存活与 pid 复用、无法核对的残留锁、两个写入者同时接管残留锁的确定性交错、锁被接管后拒绝提交）、真实 CLI 进程与插件并发写入；命令行输入上限（普通文件、FIFO、设备、stdin）、终端控制字符转义与 UTC 时间；看板版本号、增量与项目列表失效；全部 RPC（用模拟 PaseoApi，按宿主方式双向校验）；启动流程的幂等键、重复点击、跨进程重复、失败分级与中断找回；界面轮询与交互（react-test-renderer + 假时钟）；一键胶囊（顺序与逐位更新、含变量的不能一键发、只经发送账本且不会自行打断）、服务端一键发送与任务卡状态映射（含归档、删除和旧启动记录）；打包约定（Git 安装只装生产依赖、CLI 打包只含 zod 与本地源码、SDK 版本与 manifest 下限一致、图标与截图）；Playwright 在真实浏览器里跑新建、编辑、状态、删除与恢复、复制、开始处理、项目范围、首屏位置与无横向溢出、加载与错误状态。开发依赖的 `react-dom`、`react-test-renderer` 与 React 均固定为 `19.1.0`。
