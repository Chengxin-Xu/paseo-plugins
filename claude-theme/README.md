# Terracotta Themes

十二套 Paseo 主题，六深六浅，共用同一条在 OKLCH 里推导的色调阶梯与 WCAG 自动对比度拟合器；另有一个「🎨 自定义」实时主题槽：在插件设置里拖滑杆挑底色和强调色，同一套配方当场算出整套颜色，整个界面跟着变色，参数存在主机上，所有设备同步。主题在 **Settings → Appearance → Theme** 里按 emoji 列出；桌面端、浏览器和手机端都能用，只要客户端连的是装了本插件的 daemon。设置页内置英文和简体中文，也支持自定义语言。

> 非官方项目，与 Anthropic 无关，也未获其认可。配色的明度骨架取自 Claude Code CLI 内置主题的颜色值；Claude 和 Claude Code 是 Anthropic 的商标。

需要 Paseo 0.11.0 或更高版本（manifest 用了 `name`、`icon`、`media`，0.11 以前的 daemon 拒绝安装；本版在 0.11.1 上实测）。代码块的语法高亮是 Appearance 里单独的设置，不随主题变化。

插件不联网、不起子进程。主题在客户端注册；0.6.0 起多了一个服务端部分，只做三件事：

- 登记两项主机设置：自定义主题的参数和语言，由 Paseo 存在 `$PASEO_HOME/plugin-settings/<插件 id>/custom-theme.json`、`language.json`；
- 提供语言目录：启动时在 `$PASEO_HOME/plugin-data/<插件 id>/locales/` 写好 `templates/`（英文、中文模板）和说明，打开语言页时读取用户放进去的语言文件，在 `plugin-data/<插件 id>/i18n-state.json` 记下最近一台设备的语言；
- 第一次打开设置页时，把设置页的界面代码（懒加载分片）发给这台设备。

除此之外不读写任何文件。本机安装的插件 id 是 `claude-theme`，公开版是 `terracotta-themes`。

## 🎨 自定义主题（实时）

打开方式：设置 → 插件 → Terracotta 主题 → 「自定义主题」，或在命令面板里搜「调整自定义主题」。先在 设置 → 外观 → 主题 里选「🎨 自定义」，之后在调色页上的每次调整都会让整个界面换色；没选用时，页面会提示去哪里选。插件拿到的宿主主题色和自定义配色的七个颜色完全一致时才显示「正在使用」（与某套固定主题完全相同时不算）。

| 参数 | 范围 | 作用 |
| --- | --- | --- |
| 模式 | 深色 / 浅色 | 用深色或浅色那条明度阶梯 |
| 底色色相 | 0–359° | 页面、卡片、侧栏、输入框和边框偏向的颜色 |
| 底色浓度 | 0–100% | 0% 为中性灰；100% 时 `border` 彩度 0.08（十二套固定主题在 0–0.058 之间），其余表面按斜坡递减 |
| 强调色色相 | 0–359° | 主按钮、链接、选中项 |
| 强调色鲜艳度 | 0–100% | 100% 是这个色相在所用明度下 sRGB 能显示的最大彩度，所以每个色相拉满都是它最鲜艳的样子 |

- **配色还是那套配方**：参数换算成和 `SPECS` 同形的 `ThemeSpec`，交给 `paletteFor`，明度、对比度和层级都由配方和 `fitContrast` 负责。深色主题的强调色明度自动取 0.68–0.82 之间彩度最大的位置（黄、青取亮的一端，红、紫取深的一端）；浅色主题沿用配方的 0.542，不够 4.5:1 时自动压暗。默认参数是深色、底色 215° / 60%、强调色 350° / 80%：深青底配亮粉，粉色和运行中蓝、等待琥珀、失败红、完成绿都分得开，也和十二套固定主题不重样。
- **调色页**：顶部是一个小预览窗，按 Paseo 0.11 的真实表面分配画侧栏、选中行、你的消息、计划卡片、主次按钮和带占位符的输入框；下面是四根滑杆，色带画的就是滑到那里的颜色，两侧各有 −/+（步长 5，色相首尾相接），手机上也能精确调，读屏软件当作可调节控件；还有深浅切换、「随机一组」（保持深浅，底色和强调色隔着色环取一组鲜艳组合）和「恢复默认」。再往下是八个颜色的色板（带 hex，可以抄进 `SPECS`）和对比度检查。
- **对比度检查**：和十二套固定主题的测试是同一个 `evaluateThemeContrast`，25 项，按表面分组；每项用真实颜色画一个「Aa」样例，标出对比度，达标是绿色 ✓，不达标是红色 ✗ 并写出门槛。配方保证全部达标：在 3,456 种参数组合（色相每 30°、浓度 0/40/80/100%、鲜艳度 0/50/100%、深浅两种）上测试过，25 项全过，表面层级单调，次要文字和正文至少差 1.7 倍，`ring` 始终比次要文字柔和。
- **怎么做到实时**：Paseo 的 `addTheme` 只能注册和移除，没有更新。参数一变，插件就以同一个 id 先移除旧主题、再注册新主题（id 还在时重复注册会被拒绝）；Paseo 的主题目录跟着注册表更新，选中的正是这个 id 时立即换上新颜色。客户端按 `<插件 id>/theme/custom` 记住选择，刷新页面、重连后插件重新注册同一个 id，选择不丢。
- **拖动时和松手后**：Paseo 0.11.1 网页端在选中主题的颜色变化时会重建整棵界面（在两套固定主题之间切换也一样），正在进行的拖动会被打断，滚动位置回到顶部。所以拖动时只更新页面里的预览、色板和检查，松手（或点按按钮）才保存并应用；连续点按时，最后一次之后 0.25 秒应用一次。网页端在重建前记下设置页的滚动位置，重建后滚回原处。
- **颜色在哪算**：配方只在服务端和调色页里。主机设置每次读写都经过插件服务端的 schema，它按参数算出整套颜色，和参数一起存进设置、随读写结果返回；常驻客户端只拿现成的颜色注册主题。十二套固定主题的颜色在构建时算成常量（`shared/generated/themes.ts`，由 `npm run generate` 生成，测试检查它和配方逐字节一致）。调色页拖动时在本地用配方算预览，松手后写入，之后以服务端算出的颜色为准。
- **同步与流量**：参数是主机设置，保存一次写一次（同时有写入在路上时只保留最新一份）；其他设备通过 Paseo 的设置变更事件得知，读一次设置再重新注册，不轮询。两台设备同时保存时以后保存的为准。网页和桌面端在 localStorage 里留一份主机返回的设置（参数和算好的颜色），刷新页面时和十二套固定主题一起立即注册，不等读取；手机端没有插件存储，每次连接等主机返回再注册，不会先闪默认配色。读不到主机设置时先注册上次的配色（没有就在 4 秒后用默认配色），保证这一项始终在主题列表里。设置文件被手改坏时，读取会把每个值修正到范围内（色相取模，其余夹到边界，认不出的用默认值），不会让主题失效。
- **常驻成本**：每台设备连上时下载的常驻客户端包是 32,164 B（按仓库预算测试的口径，≤32 KiB）：十二套主题的颜色常量、只注册现成颜色的自定义槽，以及只带启动文字的语言运行时。配方、调色页、预览、对比度检查和语言页约 59 KB，第一次打开设置页时才下载。实际下发的字节数还包括 esbuild 给每个源文件加的路径注释（约 20 个），长度随 daemon 工作目录到插件目录的相对路径变化。

## 语言（Languages）

调色页和语言页内置英文和简体中文，默认跟随系统；在 设置 → 插件 → Terracotta 主题 → 「语言」里可以固定成某种语言。自定义主题在外观列表里的名字跟着语言走（🎨 Custom / 🎨 自定义）；十二套固定主题的名字是专有名词，不翻译。

想加别的语言：把翻译文件以 `<语言代码>.json` 放进 `$PASEO_HOME/plugin-data/<插件 id>/locales/`（本机是 `claude-theme`，公开版是 `terracotta-themes`；语言页会显示实际路径）。插件每次启动都会在那里的 `templates/` 写好英文和中文模板，复制一份改名、翻译即可；没翻译或用不了的条目显示英文，语言页会列出问题。

## 配色不是手调的

`addTheme` 只收 8 个颜色，Paseo 0.11 把它们展开成面板、菜单、diff、状态色和终端的完整 token 集：

- **浅色模式**：工作区底色 `surfaceWorkspace` = `background`，左侧栏 `surfaceSidebar` = `control`，选中侧栏项与用户消息气泡 `surface3` = `border`，输入框 `input` = `control`。
- **深色模式**：左侧栏 `surfaceSidebar` = `background`，工作区底色 `surfaceWorkspace` = `raised`，选中侧栏项、下拉浮层 `popover` 与输入框 `input` = `control`，用户消息气泡 `surface3` = `border`。
- **双模式共用**：`ring` 同时映射给焦点环、Composer 占位符 `surface4`、次级弱化文字 `foregroundExtraMuted`（消息时间戳、分组标题、工具栏图标、已完成待办文字）以及内置终端 `terminal.brightBlack`；主按钮文字 `accentForeground` = `background`。

做法是在 **OKLCH** 里推导，而不是在 hex 里试。OKLCH 的明度是感知均匀的：同一条明度阶梯换个色相，视觉深浅完全一致。于是粉色主题、靛蓝主题和深海青主题的卡片"浮起来"的程度是一样的。

骨架本身是**测**出来的：读出 Claude Code CLI（`2.1.263`）内置主题对象里的颜色，逐个换算成 OKLCH 坐标：

| Paseo token | 深色 OKLCH L | 浅色 OKLCH L | CLI 主题里的来源与 Paseo 0.11 真实用途 |
| --- | --- | --- | --- |
| `background` | 0.218 | 0.982 | 页面底色 `surface0`、深色侧栏、浅色工作区、终端底色、主按钮文字 |
| `raised` | 0.269 | 0.948 | `composerSidebarBackground:"rgb(38,38,38)"`；卡片 `surface1`、深色工作区 |
| `control` | 0.337 | 0.918 | `userMessageBackground:"rgb(55,55,55)"`；输入框 `surface2`、浅色侧栏、深色浮层 |
| `border` | 0.431 | 0.872 | `subtle:"rgb(80,80,80)"`；分隔线与用户消息气泡 `surface3` |
| `mutedForeground` | 0.683（拟合到 0.786） | 0.524 | `inactive:"rgb(153,153,153)"`；次要说明文字 |
| `ring` | 0.627（拟合到 0.640） | 0.548 | `promptBorder:"rgb(136,136,136)"`；焦点环、`foregroundExtraMuted`、占位符 `surface4`、`terminal.brightBlack` |
| `accent` | 0.670 | 0.542（自动拟合） | `claude:"rgb(215,119,87)"`（色相 **H39.1°**）；主按钮与选中强调色 |

**把彩度设为 0 喂给这套骨架，出来的就是 CLI 的深色配色**，也就是 🌑 Charcoal Night：8 个值里 6 个逐字节一致，两个文字色为 Paseo 的表面提亮了。`ring` 从 `#888888` 提到 `#8C8C8C`，因为 Paseo 深色模式把它当时间戳和分组标题画在工作区（`raised`）上，`#888888` 在那里只有约 4.3:1；`mutedForeground` 从 `#999999` 提到 `#B9B9B9`，因为宿主的状态徽标把 12px 次要文字画在 `border`（`#505050`）上，`#999999` 在那里只有约 2.8:1。这条有测试守着（`tests/palette.test.ts`）。其余十一套不是"另外画的主题"，而是同一套骨架换了色相。

### 彩度是递增的

浅色系测出来有个细节：**表面越深，彩度越高**（`#FAF9F5` C0.005 → `#DAD5C4` C0.024）。这正是奶油色和冰川蓝看起来"有设计"而不是"发灰"的原因。这条斜坡被抽成 `surfaceC: [0.22, 0.45, 0.75, 1.0]`，全家族共用。

### 刻意的偏离与自动对比度拟合（`fitContrast`）

- **`background` 是补的**：终端主题没有自己的底色（它继承终端）。深色 `#1A1A1A` 压在 composer 侧栏色下面一档，浅色用奶油白 `#FAF9F5`。
- **浅色 `ring` 针对 `foregroundExtraMuted` 调校到 L=0.548**：宿主把 `ring` 用作时间戳、分组标题、工具栏图标、输入框占位符和终端亮黑。`L=0.548` 让浅色 `ring` 既保持比 `mutedForeground`（`L=0.524`）柔和一档的层级，又在 `background` 上达到 **4.60–4.71:1（≥4.5:1）**、在 `raised` 上达到 **4.18–4.22:1**、在 `control` 上达到 **3.81–3.86:1**。
- **按宿主真实表面拟合 `mutedForeground` 与 `ring`**：深色 `ring` 对 `background` 和工作区 `raised` 同时拟合到 ≥4.5:1（六套深色主题在工作区上 4.50–4.52:1）。`mutedForeground` 除了底色和卡片 ≥4.5:1，还要在它出现的高亮表面上 ≥4.1:1：选中的侧栏行，以及状态徽标的底色 `border`（surface3）。浅色在这些表面上是 4.10–4.13:1；深色徽标从约 2.8:1 提到 4.11–4.13:1，和 Paseo 自带深色主题徽标的约 4.05:1 相当，次要文字仍明显比正文暗（对比 1.75–1.96 倍）。几组约束取更深（浅色）或更亮（深色）的那个结果，所以只会更清楚，不会变淡。
- **有意的折中，不是另一套标准**：在侧栏、浮层、输入框、选中行和徽标这些「界面框架」上，次要文字的下限低于 WCAG AA 对小字的 4.5:1。`mutedForeground` 是 4.1:1，`ring`（12px 的时间戳、分组标题）是 3.3:1，`accent` 是 3.5–3.7:1。要把时间戳也提到 4.5:1，它就会和次要文字一样深浅，层级就没了。实测浅色 `ring` 在选中行上是 3.30–3.34:1，深色是 3.54–3.59:1。正文所在的工作区仍全部 ≥4.5:1。
- **跨色相 WCAG 自动对比度拟合（`fitContrast`）**：OKLab 感知明度 $L$ 与 WCAG 相对亮度 $Y = 0.2126R + 0.7152G + 0.0722B$ 对绿、青、蓝通道权重不同，固定 `L=0.542` 在黄/绿/青/蓝色相段（$H \in [65^\circ, 270^\circ]$）会落到 4.0–4.4:1。`fitContrast` 对已达标的颜色原样返回（保证现有锚点主题逐字节不变），对不足 4.5:1 的色相保持色相与彩度、自动微调明度 $L$ 直至在 `background` 和 `raised` 上同时过 4.5:1。
- **按每个出现的表面拟合（0.6.0）**：`ring` 和 `accent` 除了对底色和卡片拟合，也按它们出现的输入框、弹层和侧栏选中行的门槛（`ring` 3.3:1，`accent` 3.7:1 / 选中行 3.5:1）拟合，几个结果取更清楚的那个。十二套固定主题本来就过这些门槛，所以颜色逐字节不变（`tests/fixtures/presets-0.5.1.json` 守着）；这一步是给自定义主题的：任意色相和浓度下，选中行和输入框上的提示文字、强调色也不会掉线。
- **🫐 Blueberry 与冷色深色主题的强调色明度**：`#B1B9F9` 保留它自己的 `L=0.8025`；`⚓ Harbor Night`（亮青 `#00C7DF`）、`🔮 Velvet Night`（亮玫粉 `#F27CC2`）、`🐬 Lagoon Night`（亮金 `#F4AF2D`）同样采用高明度鲜亮强调色，使深色界面下的主按钮文字（`accentForeground` = `background`）与表面文字双向对比度均高于 6.0:1。

### sRGB 装不下的部分

浅色底色在 L=0.982 那么亮的地方，sRGB 能容纳的彩度非常有限。🌸 Sakura 的底色请求 C0.0128，实际只拿到 C0.0087。色域拟合器的选择是**保色相、让彩度**：直接裁 RGB 通道会把粉色扭成别的颜色。所以浅色主题是"奶盖在上面"的观感：页面接近白，卡片才吃色。这是 sRGB 的硬约束，不是配置没调够。

产物在 `preview/dist/`（已 git ignore）。`scripts/preview.mjs` 按 Paseo 0.11 的真实表面分配绘制侧栏、选中行、工作区、用户气泡（`border`）、主次按钮和带占位符（`ring`）的输入框；最后一张是默认参数下的自定义主题。

## 校验

测试只用 Node 自带 runner（`node --test` + 类型擦除），不引入 vitest，依赖树 17 个包，全是开发依赖。Paseo 用 esbuild 编译插件，接受 Node 本身不认的写法（无扩展名导入、不带 `with { type: "json" }` 的 JSON、`.txt`、`.tsx`），`tests/support/` 的模块钩子补上这些（`.tsx` 用开发依赖里的 TypeScript 编译），并给宿主运行时才提供的 React Native 和客户端 SDK 换上替身，只导入不渲染。界面本身在真实 Paseo 网页客户端里验收。128 条测试：

- **色彩转换与拟合**：8 个已知色 OKLCH 往返无损；中性灰色相与彩度归零；非法 hex 抛错；色域外的颜色保住色相（漂移 <1.5°）；`fitContrast` 在全色相环 0°–360° 上保证浅色强调色对底色和卡片均 ≥4.5:1。
- **忠实度**：配方仍然复现 CLI 的深色配色（除 `ring` 提到 `#8C8C8C`、`mutedForeground` 提到 `#B9B9B9` 外逐字节一致）和 `#B1B9F9`；十二套固定主题的颜色和 0.5.1 逐字节一致（快照）；构建时生成的颜色常量是最新的，和配方算出的十二套主题、0.5.1 快照、自定义槽默认配色都逐字节一致。
- **宿主表面对比度矩阵（25 项/主题）**：每个主题对象都符合客户端的严格 schema；按 Paseo 0.11.1 的表面展开，把每个文字 token 放到它真实出现的每个表面上校验：工作区 `foreground` ≥7:1、`mutedForeground` / `ring` / `accent` ≥4.5:1；侧栏、浮层和输入框 `foreground` ≥7:1、`mutedForeground` ≥4.1:1、`ring` ≥3.3:1、`accent` ≥3.7:1；选中的侧栏行 `foreground` ≥7:1、`mutedForeground` ≥4.1:1、`ring` ≥3.3:1、`accent` ≥3.5:1；状态徽标 `mutedForeground` ≥4.1:1；用户气泡 `foreground` ≥7:1；终端 `foreground` ≥7:1、`ring`（亮黑）≥4.5:1；主按钮文字 ≥4.5:1；表面层级单调；次要文字与正文至少差 1.7 倍。
- **一致性**：同一明暗档内，各主题次要文字对比度的最大与最小值之差小于均值的 5%。主题 id 固定不变，显示名不用 Anthropic 的产品名。
- **自定义主题**：3,456 种参数组合 25 项全过、层级不乱；默认配色鲜艳且不和固定主题重样；参数归一（取整、色相取模、夹到范围、认不出用默认）、步进、深色强调色明度、鲜艳度按色域缩放、名字限 60 字符不截断 emoji；「正在使用」判断。
- **设置**：主机设置 id、作用域、版本；缺文件读成默认值；手改坏的值被修正而不是拒绝；颜色由 schema 按参数算出（存进去的颜色不算数），和常驻包用的默认配色一致；写入后读回一致。
- **常驻主题槽**：模拟 Paseo 的主题注册表（同 id 重复注册即报错）和设置存储（每次写入换 revision，过期 revision 被拒，值经插件 schema 解析）：只注册主机算好的颜色、先移除后注册、有留存先注册再跟主机（相同时不重注册）、坏的留存不用、首读超时注册默认、读失败重试（三次后等变更事件）、读不了的文件保留当前主题、另一台设备的修改、换语言重注册、名字不合规时退回英文名、清理。
- **调色页写入**：连续点按只应用一次；松手保存一次，主机的回包不再重绘；写入在路上时的点按合并成一次；写入在路上时不被别的设备覆盖，而别的设备在这次修改应用之前存下的更新配色胜出；写冲突放在最新 revision 之上；读不了的文件先重置；保存失败立即回到主机的配色并说明原因；保存失败不取消读取重试；每个主题槽只有一个写入者，设置页重建后写入照常完成。
- **入口与同步**：入口注册十二套主题、自定义槽、两个设置页和命令面板项，不提前下载设置页代码；刷新后用留存的配色在注册固定主题时一起注册，没有留存时等主机而不先画默认配色；别的设备保存后同 id 换色；清理时全部移除。设置变更事件只认本设置、跳过订阅自带的第一次快照、重连后补读；留存在内存和 localStorage 里，存储被禁用时只用内存。
- **常驻包**：从 `index.client.tsx` 沿导入链检查，常驻包里没有配方（`color.ts`、`palette.ts`、`custom.ts`）、设置 schema 和调色页代码，而分片和服务端带着它们；仓库根目录的预算测试把常驻包限在 32 KiB。
- **语言**：中英文条目和占位符一致，源码里没有没翻译的中文，每条都被用到；中英文和复数；自定义语言缺的条目退回英文；给翻译者的只有本插件用到的 kit 段落；各语言的自定义主题名都能放进主题列表。
- **打包**：manifest 与 `oss-export.json` 覆盖层合规（开源导出把 `shared/plugin-id.ts` 换成公开 id），图标是 ≥512 px 的正方形 PNG 且 `icon.svg` 色卡与锚点主题一致，截图存在且每张 ≤400 KB；Paseo 版本下限与 `@getpaseo/plugin` 的钉版一致；没有 build 命令和运行时依赖；锁文件只指向 registry.npmjs.org；预构建的设置页分片与清单一致；OVERVIEW 格式合规且不超过 1000 词。

```bash
npm run typecheck
npm test
```

设置页是懒加载分片：改了 `client/editor.tsx`、`ui-chunk.client.tsx` 等界面代码后，在仓库根目录跑 `npm run build:chunks` 重新生成 `server/generated/ui-chunk.txt` 和 `shared/generated/ui-chunk-manifest.ts` 并一起提交（`npm run check:chunks` 会检查）。改了 `shared/palette.ts` 或 `shared/custom.ts` 的配方后，在插件目录跑 `npm run generate` 重新生成 `shared/generated/themes.ts` 并一起提交（`npm test` 会检查）。

## 加一套自己的主题

在 `shared/palette.ts` 的 `SPECS` 里加一条，八行：

```ts
{
  id: "peach-latte",
  name: "🍑 Peach Latte",
  appearance: "light",
  surfaceHue: 45,          // OKLCH 色相角
  surfaceChroma: 0.05,     // border 的彩度，其余按斜坡递减
  accentHue: 30,
  accentChroma: LIGHT_ACCENT_CHROMA,
}
```

明度、对比度和层级由配方与 `fitContrast` 负责，不用自己试 hex。也可以先在「🎨 自定义」里调出满意的颜色：底色色相、强调色色相直接照抄，`surfaceChroma` = 底色浓度 × 0.08，强调色彩度和明度可以从色板的 hex 用 `toOklch` 量出来。再把新的 id 和名字加进 `tests/palette.test.ts` 开头的两份清单。`id` 发布后就别再改：客户端按 `<插件 id>/theme/<主题 id>` 记住用户的选择，改了 id 用户就会被退回默认主题；显示名可以随便改。然后：

```bash
npm run generate && npm run typecheck && npm test && npm run preview
paseo plugin reload <插件 id>
```
